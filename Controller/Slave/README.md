# Slave

`Chassis::ControllerSlave` 消费外部生成的离散轨迹点，在本地进行误差闭环跟踪，不生成路径或通信协议。依赖见 [cpkg.toml](cpkg.toml)：`Chassis::Core`、`libs::PID_PD`、`libs::RingBuffer`。实现直接使用 CMSIS-RTOS2 互斥量和中断锁；宿主必须提供相应环境，不能把包含阻塞互斥量操作的 `stop()`、`switchLoc()` 或控制权申请当作任意 ISR 可调用接口。

## 模式与对象接入

模板参数为 `Slave<BufferCapacity, Offline>`，`Offline` 默认为 `false`：

- 在线模式要求 `BufferCapacity >= 2`，通过 `pushTrajectoryPoint()` 入队、`trajectoryUpdate()` 逐点消费。
- 离线模式使用 `Slave<0, true>`，不持有轨迹缓冲，通过 `profileUpdate(point)` 直接设置当前参考点；仍由 `errorUpdate()` 完成闭环。

先建立 Motion 和可用的 Loc，再构造本控制器并通过控制权接口使其可工作；两者生命周期须覆盖本控制器。控制权、使能与就绪的区别见[仓库综述](../../README.md)。

## 轨迹点、单位与坐标系

`TrajectoryPoint` 的 `p_ref` 为世界系位姿，`v_ref` 为世界系前馈速度。位置用 `m`、yaw 用 `deg` 且范围为 `[-180, 180]`，线速度用 `m/s`、角速度用 `deg/s`；世界系必须与 Loc 一致。参考 `Posture` 构造时自动归一化 yaw，构造后直接写字段仍须自行保证范围；误差闭环默认使用劣弧角差，跨越 ±180° 不会按接近整圈的误差纠偏，恰好相差 180° 时保留原差值符号。yaw 不表示累计旋转角，不能用等效的多圈角度指定额外旋转圈数；轨迹连续性仍由调用方负责。

误差闭环与 Master 一致：先将世界系目标位姿转换为相对当前车体的位姿，再按车体各轴对零反馈计算 PD；世界系前馈速度单独转换到车体系后，与车体系 PD 输出叠加下发给 Motion。`PDConfig` 的 x/y 参数、输出限幅和微分历史均按**车体轴**解释，不再按世界轴解释；原先按世界轴整定的参数需要重新检查。轨迹点输入仍使用当前 Loc 的世界系，底层始终收到车体系速度。

## 周期与缓冲契约

在线调用顺序为：生产方 `pushTrajectoryPoint()` → 以轨迹采样节拍调用 `trajectoryUpdate()` → 在控制快环持续调用 `errorUpdate()`。离线模式以 `profileUpdate(point)` 替代入队和消费，调用方负责参考点更新节拍。轨迹点没有独立时间戳或持续时间，库不按到达时间自动重采样、插值或规划。

缓冲容量需覆盖发送与消费的累计差、突发和通信抖动。头文件中的“轨迹时长 ×（发送频率 − 消费频率）”仅可用作恒定速率下积压量的估算，不能替代容量下限或负载分析。生产速度持续大于消费速度时，有限缓冲最终仍会满。

- `pushTrajectoryPoint()` 返回 `false` 表示已满，本点没有写入，调用方必须处理。
- `trajectoryUpdate()` 仅在控制器可工作时消费；缓冲为空时保留上一次成功取得的参考**位姿和速度**，不会自动停止或把前馈速度清零。
- 缺点、断流、点间连续性和输入约束由调用方负责；本包不提供通信失联保护、轨迹平滑或自动重规划。需要停止时必须显式进入停止流程。

## 停止与交接

`stop()` 清空在线模式未消费轨迹，把当前位置设为锁定参考、前馈速度清零并重置误差 PD；继续调用 `errorUpdate()` 才能维持锁定。它不是执行器失能。`clearTrajectory()` 只丢弃尚未消费的点，不改变已生效参考点及速度，因此不能代替停止。控制权交接后按新模式显式设置新目标。

## 切换定位源

`switchLoc(new_loc)` 仿照 Master，在逻辑停止状态下切换：

- 正在跟踪时（在线成功消费或离线注入过轨迹点），取消当前跟踪，以旧 Loc 的当前位置作为锁定目标，并清零前馈速度；不等待物理底盘减速完成。
- 已停止时保留原锁定目标的车体系相对位姿，包括已有的位置和最短角误差，不重新锁定当前位置。
- 把锁定目标重映射到新 Loc 的世界系，与 Loc 指针在同一中断临界区提交；不重置 PD 历史。与显式 `stop()` 不同，切换不会清除微分历史，但取消跟踪本身仍可能改变误差和控制输出。
- 所有切换均清空在线缓冲，避免旧世界系轨迹点被新 Loc 解释。切换后保持停止，只有新轨迹点成功消费或直接注入才恢复跟踪；新点必须使用新 Loc 的世界系。

新旧 Loc 必须已可用，使用同一 Motion、车体参考点与单位，车体系运动估计基本一致；新 Loc 的生命周期须覆盖后续使用。`stop()` 与 `switchLoc()` 通过互斥量串行化，宿主仍须在控制周期边界串行化定位更新、轨迹生产/消费与误差控制，保证切换期间不会写入按旧坐标系生成的新点。该接口不是 ISR 入口，也不改变控制权或执行器使能状态。
